## Проблема

В микросервисной архитектуре бизнес-операция часто затрагивает несколько
независимых сервисов. Классический пример — оформление заказа:

1. Сервис заказов создаёт заказ
2. Сервис платежей списывает деньги
3. Сервис склада резервирует товар
4. Сервис доставки создаёт отправку
5. Сервис уведомлений отправляет письмо

Если шаг 3 завершился ошибкой, шаги 1 и 2 нужно **откатить**. Но
распределённой транзакции (2PC/XA) в микросервисах нет — каждый сервис
владеет своей базой данных.

## Решение: паттерн Saga

Saga — это последовательность локальных транзакций, где каждый шаг
имеет **компенсирующее действие** (откат). Если один из шагов падает,
оркестратор запускает компенсации в обратном порядке.

Существует два подхода:

| | Хореография | Оркестрация |
|---|---|---|
| Кто управляет | Сами сервисы (события) | Выделенный координатор |
| Связность | Высокая | Низкая |
| Сложность отладки | Высокая | Низкая |
| Видимость | Размытая | Централизованная |

**Temporalis реализует оркестрацию.**
